## 1. Slack Integration

### Status: ❌ Not implemented

### Evidence

**UI — `src/features/settings/components/IntegrationsClient.tsx`**  
Slack appears in a hardcoded "Coming soon" section alongside BambooHR, Workday, and Google Calendar. The card is cosmetic only — no `onConnect`/`onDisconnect` handlers, no OAuth flow, and the `status` is never set to `"connected"`.

```tsx
{ icon: "logos:slack-icon", name: "Slack", desc: "Send Kazi notifications to Slack channels" },
```

**No API routes** exist under `src/app/api/integrations/` for Slack. The only OAuth integration implemented is Asana (`/api/integrations/asana/connect|callback|disconnect`).

**No environment variables** — `.env.local` contains keys for Asana (`ASANA_CLIENT_ID`, `ASANA_CLIENT_SECRET`, `ASANA_REDIRECT_URI`, `ASANA_TOKEN_ENCRYPTION_KEY`) but zero Slack variables (`SLACK_BOT_TOKEN`, `SLACK_SIGNING_SECRET`, `SLACK_WEBHOOK_URL`, etc. are all absent).

**No DB schema** — no `slack_connections`, `slack_tokens`, or similar table in any migration file or `src/types/database.ts`.

**No notification delivery** — `src/lib/notifications.ts` inserts rows into the `notifications` in-app table only; there is no Slack delivery path.

### Gaps to Build
1. Slack App registration (Bot Token + Signing Secret, or Incoming Webhook URL depending on approach chosen).
2. DB table `slack_connections` (org-level webhook URL or per-user tokens).
3. OAuth flow: `GET /api/integrations/slack/connect` → `GET /api/integrations/slack/callback`.
4. Disconnect endpoint `DELETE /api/integrations/slack/disconnect`.
5. `IntegrationsClient.tsx` — move Slack card out of "Coming soon", wire connect/disconnect.
6. Slack delivery helper in `src/lib/notifications.ts` (or a separate `src/lib/slack.ts`) that posts to the workspace channel.
7. Call the Slack helper from `notifyMilestone`, `notifyCampaignLive`, and the automation runner wherever the company has Slack connected.
8. Environment variables: `SLACK_BOT_TOKEN` (or `SLACK_WEBHOOK_URL`), `SLACK_SIGNING_SECRET`.

## 2. Reward Points

### Status: ✅ Mostly implemented — critical gap: no point-awarding mechanism

### What exists

**DB Schema (`supabase/migrations/20261023000010_reward_wallets.sql`, `_0013_rewards.sql`)**
- `reward_wallets(user_id PK, balance integer ≥ 0)` — one wallet per employee
- `reward_ledger(id, user_id, amount, reason, reference_type, reference_id, created_by)` — audit trail
- `reward_catalogue(id, name, description, points_cost, image_url, is_active)` — redeemable items
- `reward_redemptions(id, user_id, catalogue_item_id, points_spent, status∈{pending/approved/fulfilled/rejected}, approved_by, fulfilled_at, notes)` — redemption lifecycle

**Typed** in `src/types/database.ts`: `RewardWallet`, `RewardLedger`, `RewardCatalogue`, `RewardRedemption`, `RedemptionStatus`.

**API Routes**
- `POST /api/pulse/rewards/redeem` — deducts points and creates a redemption + ledger entry.
- `GET/POST /api/pulse/rewards/catalogue` — list / create catalogue items (HR-gated POST).
- `PATCH /api/pulse/rewards/redemptions/[id]` — approve/reject/fulfill a redemption.

**UI (`src/features/pulse/rewards/components/RewardsPage.tsx`)**  
Full page at `/pulse/rewards`:
- Shows current balance.
- Displays reward catalogue with "Redeem" buttons (`RedeemButton.tsx`).
- Shows the user's redemption history with statuses.
- Shows pending redemptions to HR/Admin (`RedemptionActions.tsx`).

**Navigation** — `/pulse/rewards` is in the sidebar nav (`src/lib/nav.ts` line 34).

**Automations** — `award_points` is defined as a valid `AutomationAction` type in `src/types/database.ts` and surfaced in the Automations UI. The DB constraint on `automation_rules.action_type` allows `'award_points'`.

### Gaps
1. **No points are ever awarded.** `src/app/api/pulse/automations/run/route.ts` handles `send_notification` actions only — the `award_points` branch is entirely absent. There is no code path that calls `INSERT INTO reward_ledger` or `UPDATE reward_wallets SET balance = balance + N`.
2. No admin UI to manually grant points to an employee.
3. No automatic award on feedback-giving, side-quest completion, survey submission, or campaign participation (these are logical trigger points that don't currently write to the wallet).
4. Wallet rows must be created on first award (no auto-provisioning on user creation).

## 3. Automated Celebration Bots

### Status: ⚠️ Partially implemented — in-app only, missing birthday data, Slack not wired

### What exists

**Milestone generation cron** (`src/app/api/pulse/milestones/generate/route.ts`)  
Protected by `CRON_SECRET`. Generates rows in the `milestones` table for:
- `work_anniversary` — scans active users with `start_date`, creates a milestone 7 days ahead.
- `onboarding_complete` — detects new users (created ≤30 days ago) who have submitted at least one check-in.

Missing milestone generators: `birthday`, `service_achievement`.

**Automation runner** (`src/app/api/pulse/automations/run/route.ts`)  
Handles two rule types:
- `milestone_anniversary → send_notification` — calls `notifyMilestone(userId, 'work_anniversary', years)`.
- `campaign_start → send_notification` — notifies all active users when a campaign goes live.

**Notification helpers** (`src/lib/notifications.ts`)  
`notifyMilestone` supports all four milestone types in its label logic (`birthday`, `onboarding_complete`, `service_achievement`, `work_anniversary`), but only inserts rows into the in-app `notifications` table.

**Dashboard widget** (`src/features/pulse/dashboard/components/MilestonesWidget.tsx`)  
Renders upcoming milestones (next 7 days, unacknowledged) on the Pulse dashboard. Shows the four types with appropriate icons.

**DB** (`supabase/migrations/20261023000014_milestones.sql`)  
`milestones(id, user_id, type∈{work_anniversary,birthday,onboarding_complete,service_achievement}, milestone_date, years_count, acknowledged)`.

**Automations UI** (`src/features/settings/components/AutomationsClient.tsx`)  
HR/Admin can create rules with trigger `milestone_anniversary` + action `send_notification` (or the stub `award_points`).

### Gaps
1. **Birthday DOB not stored.** The `users` table has no `date_of_birth` column — there is nothing to generate birthday milestones from. A migration adding `date_of_birth date` to `users` and a birthday generation block in the cron route are both missing.
2. **`service_achievement` has no generation logic.** The milestone type exists in the DB enum and notification labels but is never generated.
3. **No Slack/email delivery.** All celebration notifications are in-app only. A celebration "bot" (Slack message, email, or both) requires hooking the automation runner into `src/lib/slack.ts` (not yet built) and/or `src/lib/email.ts`.
4. **`award_points` automation is a no-op.** A rule of `milestone_anniversary → award_points` can be created in the UI and saved to the DB but does nothing when the cron fires.
5. No acknowledgment flow (the `acknowledged` column exists on `milestones` but nothing sets it to `true` from the UI).

## 4. Walk of Fame & Milestone Tracking

### Status: ⚠️ Partially implemented — Culture Leaderboards exist; no Walk of Fame; limited milestone types

### What exists

**Culture Leaderboards page** (`src/features/pulse/leaderboards/components/LeaderboardsPage.tsx`)  
Full page at `/pulse/leaderboards`:
- Opt-in (`show_on_leaderboard` per user in `engagement_notification_preferences`).
- Admin toggle (`culture_leaderboards_enabled` on `company_settings`).
- Five boards, last 90 days: Campaign participation, Side Quests completed, Quiz scores, Recognition givers, Recognition receivers.
- Top-5 per board with rank badges and counts.
- Navigation in sidebar (`src/lib/nav.ts` line 33).

**Leaderboard opt-in DB** (`supabase/migrations/20261023000016_leaderboard_opt_in.sql`)  
`engagement_notification_preferences(user_id PK, show_on_leaderboard boolean DEFAULT true, ...)`.

**Milestone tracking (in-app widget)** (`src/features/pulse/dashboard/components/MilestonesWidget.tsx`)  
Shows upcoming milestones on the Pulse dashboard. Types: `work_anniversary`, `birthday`, `onboarding_complete`, `service_achievement`.

**Milestone DB** supports `years_count` on work anniversaries.

### Gaps
1. **No Walk of Fame / Hall of Fame feature.** There is no dedicated spotlight page, no public employee profile with achievements, no "top hires closed by recruiter" board, and no concept of a permanent record of excellence vs. a rolling 90-day leaderboard.
2. **Hiring-count milestone missing.** No tracking of "recruiter closed N hires" milestone — neither in `milestones` types nor as a leaderboard board.
3. **Long-service milestone missing.** 5-year, 10-year, etc. service achievements are a type in the DB enum but are never generated by the cron job (`service_achievement` generation logic is absent).
4. **Leaderboard is participation-only, not performance.** It counts activity (recognitions, quest completions) rather than quality or impact metrics, which may not satisfy a "top performers" requirement.
5. **No permalink / shareable profile.** There is no public-facing employee page for sharing achievements or recognitions.
6. **`acknowledged` column exists but is unused** — no UI to mark milestones as celebrated/acknowledged.

## Recommendations

### Priority order to build

**1. Slack Integration (highest user-visible impact)**
- Register a Slack App with `chat:write` + `incoming-webhook` scopes.
- Add `SLACK_BOT_TOKEN` / `SLACK_WEBHOOK_URL` to env.
- Create `src/lib/slack.ts` with a `postSlackMessage(channel, text, blocks?)` helper.
- Add `slack_connections` table (org-level, stores webhook URL or bot token + channel ID).
- Build OAuth flow at `/api/integrations/slack/connect|callback|disconnect`.
- Wire `src/lib/notifications.ts` helper functions to also call Slack when a connection exists.
- Promote the Slack card in `IntegrationsClient.tsx` out of "Coming soon".

**2. Points awarding (Reward Points is 80% done — just needs the credit side)**
- Implement the `award_points` branch in `automations/run/route.ts`: read `config.points` from the rule, upsert the wallet row, insert a ledger entry.
- Add a manual "Grant points" admin action in the Rewards settings.
- Optionally award points on: feedback given, side-quest completion, survey submission.

**3. Birthday milestones (small DB + cron change)**
- Add `date_of_birth date` column to `users` table (nullable, migration needed).
- Add birthday generation block to `milestones/generate/route.ts`.
- Add `date_of_birth` field to staff profile edit forms.

**4. Walk of Fame**
- Design as a new page `/pulse/walk-of-fame` showing:
  - All-time top recipients of public recognition.
  - Tenure badges (1yr, 3yr, 5yr, 10yr).
  - Optionally: top recruiters by hires closed.
- Requires: long-service milestone generation, hire-count data query from `candidates` table, a dedicated page component.

**5. Service achievement milestones**
- Add generation logic to `milestones/generate/route.ts` for 1, 3, 5, 10 year anniversaries (separate from work_anniversary or reusing `service_achievement` type with `years_count`).

### Not needed to build
- The core automations UI and rule engine already exist.
- The leaderboard infrastructure (opt-in, admin toggle, 90-day boards) is solid.
- The rewards catalogue + redemption flow is complete.
- The milestones dashboard widget is ready — it will display birthday milestones once DOB data exists.
